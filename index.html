⚙️ 解密配置

📦 存储说明
算法、域名规则、模板保存在 localStorage；第三方库保存在 IndexedDB，并按需懒加载。
重启应用数据不丢；可编辑内置算法（显示「已覆盖」，可一键重置）。
⚠️ 清除应用数据会丢配置，建议用「💾 备份 (json)」定期导出。
💡 「📥 导入算法 JS」从外部 .js 文件导入算法/规则/模板，文件中需赋值 window.HAR_DECODERS / window.HAR_RULES / window.HAR_TEMPLATES。导入会覆盖同 ID 的算法。
只有此算法第一次用到时才加载对应库。库名要与「第三方库」Tab 里保存的库名一致。
如算法里写 CryptoJS.AES.decrypt(...)，这里就填 CryptoJS。
签名：function(text, ctx) 或 async function(text, ctx)。
text 是 HAR 里未做任何处理的原始字符串（query / body / response / 字段值 / 请求头）。
需要二进制（AES 密文、gzip 流等）时，函数内部 atob(text) 自己转字节。
可用：pako、smartDecodeText / smartDecodeValue、base64ToBytes / bytesToBase64Str、以及在「第三方库」中声明依赖的全局名。
签名：function(value, ctx) 或 async function(value, ctx)。
value 是解密结果（对象 / 字符串），返回字符串 —— 即网络传输时的样子（如 base64 密文）。
保存后可用于「🔒 加密对照」：encode(decode(原文)) === 原文 严格字符串比较。
📚 库管理（懒加载）
把 UMD / IIFE 库代码粘贴到下面，或把 .js 文件拖拽进来。库代码保存到 IndexedDB，重启不丢。
不会在启动时加载：只有当某个算法声明了「依赖库」并第一次用到该算法时，才把库注入全局。
